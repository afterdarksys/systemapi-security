# secsvc hardening, batch 1: contract

2026-11-22. Source: the independent audit of `289299c`. Branch: `fix/hardening-1`.

Every fix below comes with:
- a test that fails if the fix is reverted;
- a `Threats:` note in the code it changes;
- a stable code from `internal/codes` for each refusal.

| # | Problem | Fix |
| --- | --- | --- |
| S1 | Truncating or deleting the audit chain goes undetected. Appends restart at seq 1. | A local anchor, `audit.head`, kept next to `audit.jsonl`. It holds the last seq and the hash of the last row, and is written atomically after each append (temp file, fsync, rename, directory fsync). Verify and open fail with `audit_truncated` when the chain ends before the anchor's seq or hash, or when the chain is missing while the anchor exists. The anchor is created with the first row; an empty chain with no anchor is a fresh store. **Residual:** root can rewrite both files. An off-host anchor is a later batch, through the agent. Docs must say this plainly. |
| S2 | A FIFO or other special file hangs the daemon: status blocks while holding `e.mu`, and the IDS goes silent. | Every scan and status open of a configured path uses `O_NONBLOCK\|O_NOFOLLOW` (as modules already does). It then checks with fstat that the file is regular before reading. A non-regular file is a finding or coverage error (`not_regular`), never a blocking read. Reads have a size cap. |
| S3 | `POST /v1/scan` never spends its lease, so one grant replays for 15 minutes. | A scan spends its lease exactly once, as config mutations do. A second scan with the same grant is refused with `lease_spent`. Update the test that scans with an already-spent lease. |
| S4 | A config grant scoped to one path can change global settings (`listen_allow`, `auth_fail_limit`, `auth_window_s`). | `AllowChange` treats every global field as needing a grant whose coverage includes it. A narrow-path grant can change only the watch entries it covers. Otherwise `config_scope`. |
| S5 | Integrity baselines record only the 0777 bits. Setuid/setgid/sticky, uid and gid changes go unreported. | The baseline records the full mode bits (including setuid, setgid and sticky), uid, gid and file type. A change to any of them is a finding. The baseline format is versioned. An old baseline is re-taken once, with an audit row, instead of silently compared. |
| S6 | The shipped unit pins `--host localhost`. | The unit and the service templates take the host from configuration with no default value. `serve` refuses `localhost` and empty with `host_unset`. A test checks this. |
| S7 | Auth-log tailing has three problems. **(a)** It misses rotation when the new file grows past the saved offset. **(b)** The first scan dates old lines "now" and pages on them. **(c)** It takes the IP from attacker text. | **(a)** Track inode and device as well as offset: a different inode, or a size below the offset, means rotation. **(b)** On the first scan with no saved state, start at the end of the file (the baseline) and do not page on history. **(c)** Parse the IP only from the fixed sshd message structure: the token after the last ` from ` that precedes ` port `. It must parse as an IP. Otherwise no IP is reported. |
| S8 | Caps reports `covered` when it is not. | The integrity cap is `ok` only when every watched path exists and is baselined, otherwise `degraded` with a reason. `grant_v1` reports whether a public key is loaded. Status never claims coverage it lacks. |
| S9 | The shadow-file group owner is not checked. | The permissions module checks the shadow file's group: root, or the distro's shadow group. A finding otherwise. |
| S10 | Grants have no not-before. A far-future grant becomes usable in its last 15 minutes. | Grants carry `iat`, signed. The daemon refuses a grant with `iat` in the future (beyond 60 seconds of skew), or with `exp - iat` above the 15-minute ceiling. Old grants without `iat` are refused (`grant_bad_shape`). This is a format change, so the version is bumped to `secsvc/2`, and the Go vectors are updated. |
| S11 | Leftovers from earlier tools. | Remove `modules.RequiredPaths` (only tests call it, and its comment claims it is the grant gate). Remove the `ntfy` substring check, which can never match. Make the blocked documentation ranges match the comment by adding 2001:db8::/32. |

## Decisions made during the build

- **S1.** The anchor sits next to the chain by name (`audit.jsonl` gives `audit.head`) and is read before the chain. The chain may be at the anchor's seq or exactly one row past it (a crash between the row and the anchor, moved up on open); anything else is `audit_truncated`, as is a different hash at the anchor's seq. A malformed or symlinked anchor is `audit_bad`. After review there is no upgrade path: a non-empty chain with no anchor is `audit_truncated` at open, in verify, and at runtime. At runtime `ReadAll` also requires the row this chain last wrote to still be on disk with the same hash, so deleting the anchor and truncating under a live daemon is caught. A pre-anchor chain is anchored only by the operator with `secsvc audit anchor --dir D`, which verifies the whole chain, writes the anchor, and appends `audit.anchor_init` with the seq and hash it anchored. It refuses with `anchor_exists` when an anchor exists, and with `store_busy` while another process holds `lock`, a POSIX record lock that `store.Open` takes for the process lifetime. Record locks are per process, so they do not stop a second open inside one process. Inside a running chain `ReadAll` requires exactly the rows this chain wrote, the last with its hash; the one-row crash allowance applies only at open. `secsvc audit verify` retries briefly before reporting `audit_truncated`, because the daemon writes the row before the anchor. The audit and store state files are opened `O_NONBLOCK|O_NOFOLLOW` and checked with fstat, like configured paths.
- **S2.** `not_regular` is the internal code. Findings keep their existing kinds (`integrity_not_file`, `auth_log_unavailable`) and the capability reason stays `unreadable`, because the reason set is closed. The CLI reads of operator-named grant, contact, and config files and the fixed `/proc/net` reads are not configured scan paths and were not changed.
- **S3.** The refusal is the existing `grant_spent`, not a new `lease_spent`: a scan now uses the same `Store.Spend` as config, baseline, and contact, and a second code for the same condition would split callers. The internal loop passes no lease and spends nothing.
- **S4.** Coverage of a global field means coverage of what it governs. `listen_allow` (compared as a set) needs `/proc/net/tcp` and `/proc/net/tcp6`, for example `--watch /proc/net`. `auth_fail_limit` and `auth_window_s` need every `auth_log` set before or after; with no auth log on either side they are refused, so nobody can pre-set thresholds for a log they cannot cover. Global refusals are `config_scope` (403); an uncovered changed path stays `forbidden` as before.
- **S5.** `baseline.json` is `{"v":2,"records":{...}}`; a bare map is version 1. After review there is no upgrade: adopting the file's current setuid bit, uid, or gid would bless a change made before the upgrade. A version-1 baseline loads as no records, so every watched path is `integrity_unbaselined` (medium) and the cap is `unbaselined` until an explicit `POST /v1/baseline`, which writes version 2 with its `baseline.set` row. An open integrity finding on a watched path with no baseline record is retained, never resolved, so a version-1 file cannot turn a high change into a medium unbaselined; an explicit re-baseline is still the operator's decision to accept the file as it is. A metadata-only change has summary `mode or owner changed`.
- **S6.** sahinit does not expand variables, so `units/secsvc.json` ships `--host ""` and the operator edits it; serve refuses until then. The systemd and OpenRC templates ship empty values. `host_unset` covers empty, `localhost`, `localhost.localdomain`, `ip6-localhost`, `ip6-loopback`, `localhost6`, `localhost6.localdomain6`, any name under `.localhost`, and any IP literal. Names are not resolved, so startup does no DNS and a name that resolves only to loopback is not caught. A missing `--host` flag is `host_unset` rather than `usage`.
- **S7.** The position (path, inode, device, offset) is stored in `ids-state.json` as additive fields. State written by an older binary has no path, so its first scan after upgrade starts at the end: lines written between the last old scan and the upgrade are skipped rather than paged on. PAM `rhost=` is no longer read for the summary IP. Copytruncate rotation keeps the inode, so lines written after the copy and past the saved offset before the next scan can be missed; this is documented, not fixed. The device half of the check has its own test.
- **S8.** The capability keeps the name `grant_v1` so the registry stays stable. Two reasons were added to the closed set: `unbaselined` and `no_key`.
- **S9.** Debian, Ubuntu, and Alpine allow the `shadow` group, resolved by name from `/etc/group`; Red Hat, Rocky, and Arch allow root only. The rule covers `gshadow` too. An unreadable or malformed `/etc/group` is incomplete coverage, not a pass.
- **S10.** A future `iat` is a new code, `grant_future` (401). `exp` not after `iat` is `grant_ttl`. The old `exp <= now + 900` check stays. `secsvc grant` signs `iat` as now. There were no vector files outside the Go tests; those were updated, and a correctly signed `secsvc/1` document is a test case that must be refused. A v2 document signed over the v1 domain string is refused too, which pins the domain.
- **S11.** The two removals have no test that fails on revert, because the removed code had no reachable effect. The `2001:db8::/32` block has one.
- **Breaking changes** are listed in README.md: re-sign grants, set a real `--host`, run `secsvc audit anchor` once on an existing chain, and re-baseline a version-1 baseline.
- **Not in this batch, still open:** the off-host anchor and audit rotation; the ntfy topic exposure note; the API write timeout.
